# 03 配置参考

配置来源只有两个本地文件 + 一组环境变量，**没有数据库**：

- `haproxy.cfg` —— 负载均衡配置的唯一权威（rl-limiter 只读）；
- rl-limiter 的 YAML（`-c` 指定，默认 `/etc/rl-limiter/config.yaml`）；
- 环境变量 —— 网卡接线、控制台、令牌等进程级开关。

两个文件被运行期轮询（5s），内容变化即热生效（**热更性**见各字段标注）。
带全量注释的 YAML 示例在 `deploy/config/limiter.example.yaml`，容器模板
在 `deploy/docker/limiter-node.yaml`。

## 1. YAML 字段

### 顶层

| 字段 | 默认 | 热更 | 说明 |
| ---- | ---- | ---- | ---- |
| `log_level` | `info` | ❌ 重启 | debug/info/warning/error |
| `tick_interval_s` | `1.0` | ❌ 重启 | 采样周期（秒） |
| `haproxy` | — | ❌ 重启 | 本机 HAProxy 接线，见下 |
| `quotas` | `{}` | ✅ | frontend 名 → **出向带宽目标**（Mbps） |
| `request_limits` | `{}` | ✅ | frontend 名 → 入向限速登记，见下 |
| `instance_quota_mbps` | 0（不限） | ✅ | **实例出向总带宽目标**（Mbps） |
| `dynamic_ingress` | 见下 | ❌ 重启 | 闭环控制器参数 |

启动时定型的字段改了会在日志里 warning 提示"热更新不生效，请重启"。
写 API（及控制台配置页）只开放热更字段，且仅限限额类——这是有意的
边界，见 `rl_limiter/configstore.py` 头注释。

### `haproxy` 段（采样通道二选一，校验强制恰好一种）

| 字段 | 说明 |
| ---- | ---- |
| `name` | 实例名（日志/页面展示，默认 `haproxy`） |
| `socket_path` | 本机 unix stats socket（**同机部署，推荐**）。haproxy.cfg 里需有 `stats socket /var/lib/haproxy/stats mode 660 level user` |
| `host` / `port` | 内网 TCP stats socket（远程只读观测的兼容形态） |
| `cfg_path` | haproxy.cfg 路径（解析受管清单用） |
| `timeout_ms` | 采样超时（默认 500） |

### `quotas` 段

```yaml
quotas:
  fe_main: 40        # fe_main 的出向带宽目标 40Mbps
  fe_api: 0          # 显式不限（0 与"不登记"在告警/闭环上等价，
                     # 但 0 是看得见的决定，不会触发"未登记"的启动提醒）
```

**本分支语义**：quotas 是闭环的**出向目标**（判断基准），不直接驱动
出向整形（`RL_TC_IFACE=-` 时）。单网卡形态（设了 `RL_TC_IFACE`）下
它同时是出向 HTB 的限额。持续超限告警的基准也是它。

### `request_limits` 段

```yaml
request_limits:
  fe_main:
    mbps: 10         # 入向带宽上限（闭环动态值的上限；0 = 不限带宽）
    conn_rate: 150   # 每秒新建连接（SYN）上限（静态执行；0/缺省 = 不限）
```

- 闭环开着且该 frontend 有出向目标时，`mbps` 是动态调节的**上限**，
  实际下发值由控制器决定（看控制台调节视图）；没有出向目标时按静态值
  直接下发；
- 配置了 `request_limits` 而入向执行网卡（默认 eth0）在本机不存在 → **启动失败**（宁可
  起不来，也不要以为限了请求方向其实没有）。

### `dynamic_ingress` 段（闭环控制器，启动时定型）

| 字段 | 默认 | 说明 |
| ---- | ---- | ---- |
| `enabled` | **`true`（默认启用）** | 开关。闭环是出厂形态（出向不整形 + 入向 eth0）下限速的唯一执行者，默认即开；基线出向 HTB/纯监控形态写 `false` 关闭。入向未接线（`RL_TC_IN_IFACE=-`）时控制器自然不跑（手写 true 才告警） |
| `interval_s` | `15` | 调节周期（≥5；观测窗口 10s，别调得比它快） |
| `low_ratio` / `high_ratio` | `0.85` / `1.0` | 死区 [low, high]×目标 |
| `step_up` | `0.05` | 单次上调步长（×当前值，乘性；绝对下限 0.1Mbps） |
| `step_down_max` | `0.10` | 单次下调封顶（×当前值，乘性） |
| `floor_ratio` | `0.10` | 动态值下限（×上限；实例环落位后改锚落位值）。下载型业务 ACK 杠杆高，建议留低（demo 用 0.05），否则会"压到下限、出向仍高于目标" |
| `apply_epsilon` | `0.02` | 低于该比例的变化不下发 |

各参数在算法里的角色见 [02 闭环限速原理](02-闭环限速原理.md) §3。

## 2. 环境变量

| 变量 | 默认 | 说明 |
| ---- | ---- | ---- |
| `RL_TC_IFACE` | `-`（出向整形关闭，闭环形态） | **出向** HTB 整形网卡；要出向直接整形（典型：单网卡机器）显式填网卡名 |
| `RL_TC_IN_IFACE` | `eth0`（出厂接线约定：客户端侧） | **入向**执行网卡 = 客户端侧网卡。非 eth0 命名的机器显式指定，**不做自动探测**（放错网卡会误伤后端流量）；`-` = 显式关闭。默认值下本机没有 eth0：配了限速启动失败，纯监控降级为告警 |
| `RL_TC_IN_MODE` | `ifb` | 入向执行模式：`ifb`（IFB+HTB 平稳整形）/ `police`（超额丢包，老内核备选，实例总闸不可用） |
| `RL_TC_IFB` | `ifbrl0` | IFB 设备名 |
| `RL_NIC` | 本机全部**物理**网卡（容器等探测不到物理网卡时回退跟随执行网卡） | 实例面板按设备统计（带宽/包/丢包）的网卡清单，逗号分隔可多张；首卡为"锚点"（老的单卡字段镜像它，默认把执行网卡排最前）；`-` = 禁用 |
| `RL_CONSOLE_PORT` | 未设 = 不启控制台 | 控制台端口 |
| `RL_CONSOLE_BIND` | `0.0.0.0` | 控制台监听地址（默认内网同网段可直接打开）。读接口无鉴权，必须由防火墙/安全组限制来源（绑非回环会打 warning 留痕）；只想本机访问改 `127.0.0.1` |
| `RL_API_TOKEN` | 未设 = 写接口整体 403 | 写 API 令牌（页面改限额也走它） |
| `RL_METRICS_LOG` | 未设 = 不落盘 | 监控数据 JSONL 路径（分钟粒度，按天轮转） |
| `RL_METRICS_LOG_DAYS` | `90` | 落盘保留天数 |

容器入口脚本（`deploy/docker/node-entrypoint.sh`）另有：

| 变量 | 说明 |
| ---- | ---- |
| `RL_FRONT_SUBNET` | 客户端侧网段前缀（如 `10.211.1.`）：按网段定位客户端侧网卡并导出 `RL_TC_IN_IFACE`（显式给的优先）。容器里网卡名不稳定时用它 |
| `HAPROXY_MAXCONN` / `HAPROXY_MAXPIPES` | 覆盖模板里的对应 directive（演示降量级用；生产独占机器删掉用模板默认） |
| `HAPROXY_NBTHREAD` | 覆盖/插入 nbthread（同机多实例演示防线程超配；生产删掉自动=核数） |
| `PIP_INDEX_URL`（构建参数） | 构建时换 pip 源（公司内网 DNS 挡 pypi 时用） |

## 3. 命令行

```
python3 -m rl_limiter -c /etc/rl-limiter/config.yaml    # 启动
python3 -m rl_limiter --version                         # 打印版本
```

## 4. haproxy.cfg 的约定

rl-limiter 解析 cfg 里的 `frontend`/`listen` 段得到受管清单（名字、
bind 端口、mode）。要求：

- 每个受管段有**确定的 bind 端口**（tc 按端口分类）；
- `stats socket` 行与 YAML 的 `socket_path` 指同一处，且 rl-limiter
  进程用户可读写（裸机部署时靠 haproxy 属组，装机脚本会处理）；
- 给不存在的段名登记限额：写 API 直接 400 拒绝；手工写进 YAML 会被
  cfgparse 忽略并 warning。

**FD 预算**：HAProxy 需要 maxconn×2 + maxpipes×2 + 34 个 fd。模板
`deploy/docker/haproxy-base.cfg` 的默认值是 100 万连接（= 400 万 fd），
需要先抬宿主机 `fs.nr_open`（见 [08 内核参数调优](08-内核参数调优.md)）；
入口脚本会按 cfg 实际值预检并直接报出该改成多少。

## 5. 写 API 回写的注意事项

- 回写 = 读文件 → 改内存结构 → **与启动完全相同的校验链**验证整份
  配置 → 临时文件 + `os.replace` 原子替换。校验不过就拒绝，文件一个
  字节不动——绝不会写出一份"重启就起不来"的 YAML；
- **手写注释会丢**（YAML 数据往返的限制），文件头部会注明。想保留
  注释的运维直接编辑文件即可，两条路最终效果一致；
- 进程外同时手工编辑时，最后写的赢（与两个运维同时改文件的语义相同）。
