# 限速服务（rl-limiter）运行指南

> 对应设计：[01-方案设计.md](01-方案设计.md)。本文覆盖安装、配置来源、
> 本地演示与 HAProxy 侧前置条件。docker compose 一键演示（含 Web 控制台
> 玩法）见 [04-DockerCompose演示.md](04-DockerCompose演示.md)。

**架构一句话**：一个独立部署的 rl-limiter 服务通过内网 TCP 连接多台
HAProxy 的 stats socket，每秒采样各节点 frontend 的 `bytes_out`，**按
节点**做 AIMD 决策并把整形值写回该节点的 bwlim map——每台节点自己设置
带宽限制、独立调节；业务环境是节点分组，仅提供聚合查看。

单位约定：配置里的 `quota_bps` 一律为 **bit/s**（40000000 = 40 Mbps），
服务内部统一使用 **bytes/s**（唯一换算点在 `rl_limiter/model.py` 的
`EnvQuota.quota_bytes_per_sec`）。

## 1. 安装

要求 Python ≥ 3.11。依赖：PyYAML、aiohttp、aiomysql、cryptography
（MySQL 8+ 默认认证需要）。

```bash
pip install -e ".[test]"    # 或 make install
make test                   # 全部单元测试
rl-limiter --version        # 验证入口可用
```

## 2. 配置来源（二选一）

### 2.1 MySQL 配置库（生产推荐）

设置 `RL_MYSQL_HOST` 即启用：启动时从库加载全量配置（等库就绪最长
120s），运行期每 `RL_MYSQL_POLL_S` 秒轮询热更新。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `RL_MYSQL_HOST` | 无（必设才启用） | 配置库地址 |
| `RL_MYSQL_PORT` | `3306` | |
| `RL_MYSQL_USER` / `RL_MYSQL_PASSWORD` | `rl` / 空 | |
| `RL_MYSQL_DB` | `rl_limiter` | |
| `RL_MYSQL_POLL_S` | `5` | 配置轮询周期（秒） |
| `RL_CONSOLE_PORT` | 无（必设才启用） | 内置 Web 控制台端口（只绑内网/防火墙内） |

表结构与种子示例：[deploy/mysql/init.sql](../deploy/mysql/init.sql)；
热更新边界与常用 SQL 见 [04-DockerCompose演示.md](04-DockerCompose演示.md)。

### 2.2 本地 YAML（standalone / 开发）

不设 `RL_MYSQL_HOST` 时读取 `-c` 指定的 YAML（默认
`/etc/rl-limiter/config.yaml`），完整注释示例见
[deploy/config/limiter.example.yaml](../deploy/config/limiter.example.yaml)：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `mode` | `dry-run` | 全局默认模式：`dry-run` 只打日志；`enforce` 真实写 map |
| `log_level` | `info` | debug / info / warning / error |
| `tick_interval_s` | `1.0` | 快环节拍（秒），设计基准为 1 秒 |
| `haproxy_nodes[].name` | 必填 | 节点名，`envs[].targets[].node` 引用它 |
| `haproxy_nodes[].host` / `port` | 必填 | 该节点内网 TCP stats socket 地址（`level admin`） |
| `haproxy_nodes[].quota_bps` | 被挂载节点必填 | **该节点自己的带宽限制**（bit/s） |
| `haproxy_nodes[].mode` | 空=继承全局 | 按节点模式覆盖（`dry-run`/`enforce`），逐台灰度用 |
| `haproxy_nodes[].params` | 缺省用默认 | 按节点 AIMD 参数覆盖（1.10 / 0.90 / 3s / 5s / ×0.9 / 1.00 / +5%） |
| `haproxy_nodes[].bwlim_map_path` | `/etc/haproxy/maps/bwlim.map` | 与该节点 haproxy 配置中 `map_str_int(...)` 路径一致 |
| `haproxy_nodes[].timeout_ms` | `500` | 单次 runtime API 命令超时（毫秒） |
| `envs[].env_id` | 必填 | 环境 ID（**纯分组**：环境不携带配额/参数） |
| `envs[].targets[]` | 必填（≥1） | 挂载点：`{node, frontend}`；节点是环境的独占资源 |

## 3. 本地 dry-run 演示（无需真实 HAProxy / MySQL）

仓库自带联调工具：`tools/fake_haproxy.py`（假 stats socket，`show stat`
计数器按指定速率增长，`set map` 记录并打日志）。

**终端 1、2：两台假 HAProxy**

```bash
python3 tools/fake_haproxy.py --port 19991 --frontends fe_env_a:2000000
python3 tools/fake_haproxy.py --port 19992 --frontends fe_env_b:500000
```

**终端 3：限速服务（standalone YAML）**

```bash
cp deploy/config/limiter.example.yaml /tmp/limiter.yaml
# 编辑 /tmp/limiter.yaml：
#   hap-1: host 127.0.0.1, port 19991；hap-2: host 127.0.0.1, port 19992
#   （示例里各节点已带 quota_bps）
rl-limiter -c /tmp/limiter.yaml
```

可观察到的行为：

- 启动即打 `服务配置加载完成，以下为完整配置摘要 ...`（config_source=
  文件 ...），随后 `已用本地静态配置完成引导（控制单元=节点） ...`；每分钟一条
  `运行状态周期汇总（每 60 拍输出一次） ... envs_summary=hap-1:mean10_bytes_per_s=...`
  ——控制单元即节点，汇总按节点名列出；
- 节点用量超过其 `quota_bps` 后，日志出现收紧状态变迁与（dry-run 下）
  `【DRY-RUN 演练】本应下发整形值 ...`；把 YAML 里 `mode` 改为
  `enforce` 重启后，fake_haproxy 侧打出
  `收到 map 更新，本节点限速值已改写 ... key=fe_env_a old=... new=...`；
- 停掉一台 fake_haproxy：该节点进入 degraded（周期汇总的
  `degraded_nodes` 列出），其限速值冻结（fail-static），另一台节点完全
  不受影响；拉起后自动恢复。

想连同 MySQL / Web 控制台 / 真实 HAProxy 一起演示，直接用
`make demo-up`（docker compose，见 docs/04）。

## 4. HAProxy 侧前置条件（每台受控节点）

- **版本 ≥ 2.8**（`bwlim` 过滤器 2.8 起正式；无法升级的节点只能退化为
  tc 单层硬限）。
- `global` 段开启**内网 TCP** stats socket：

  ```
  stats socket ipv4@<内网IP>:9999 level admin
  ```

  **安全须知**：admin 级端口等同于 HAProxy 的完全控制权。只允许绑内网
  IP，绝不可绑 0.0.0.0；安全组/防火墙仅放行限速服务器的 IP。可同时保留
  一行本机 unix socket 用于应急运维（见示例 cfg 注释）。
- map 文件 `/etc/haproxy/maps/bwlim.map` 必须在 HAProxy 启动前存在
  （解析期加载），每行 `<frontend名> <bytes/s>`；运行期条目归 rl-limiter
  所有，经 runtime API `set map` 更新，改限速不需要 reload。
- **TCP L4 整形接线**（`listen` + `tcp-request content`，含 map 未命中
  兜底与逐行说明）见
  [deploy/haproxy/bwlim-example.cfg](../deploy/haproxy/bwlim-example.cfg)。
  两条 L4 语义务必知晓：每连接限速在**建连时定格**（map 更新只影响新
  连接）；经整形入口的流量应使用 keep-alive / 客户端侧关连接（服务端
  先 FIN 会与整形数据竞争导致响应截断）。
- 内核层兜底部署在**各 HAProxy 机器本机**：
  [deploy/tc/backstop.sh](../deploy/tc/backstop.sh)，速率取节点限制的
  115%，如 40 Mbps 限制 → `./backstop.sh eth0 46`。它与 rl-limiter 服务
  无关，rl-limiter 也因此不需要 CAP_NET_ADMIN。

## 5. 容错行为表（设计 §3.7）

| 故障 | 行为 |
| --- | --- |
| 某台 HAProxy 节点失联 | 该节点采样失败当秒沿用上一秒速率；连续失败进入 degraded（周期汇总与控制台节点面板可见），该节点限速冻结不动；节点上残留的 map 值保持最后一次写入（安全方向），该机 tc 兜底仍在内核生效；恢复后自动解除。**其它节点不受影响** |
| MySQL 配置库断联 / 宕机 | 按最后一次加载的配置继续限速（fail-static）；启动阶段等库就绪最长 120s（凭据/依赖类永久错误立即失败）；单次拉取带整体超时，静默网络分区不会卡死轮询 |
| 配置写错（含引用运行期新增节点） | 整份快照被拒绝，保留当前配置继续限速并打日志；控制台/写库入口对常见错误（配额非法、挂载点冲突、节点被他环境占用）当场返回中文错误 |
| rl-limiter 自身宕机 | systemd `Restart=always` 2 秒拉起；离线期间各台 HAProxy 保持最后写入的 map 限速值不变 + 各机 tc 兜底仍然生效，限速不会放开 |
| dry-run → enforce 切换（全局或单节点） | 配置先于 tick 生效；切到 enforce 的节点做一次性全量重写（resync），消除演练期间的陈旧 map 值 |
| enforce → dry-run | 只停止更新 map；已下发的整形值继续生效（fail-static，绝不主动放开限速） |

## 6. 尚未包含（后续里程碑）

- **管理后台**：配额审批/审计、对账报表、告警（M4）。配置权威是 MySQL
  配置库，后台建设时应直接读写配置库。
- **tc 自动化**：backstop.sh 需在各 HAProxy 机器上手工执行，rl-limiter
  不校验/不维护 tc 规则。
- **指标外呈**：无 Prometheus 端点/Grafana 大盘（观测走内置 Web 控制台
  与结构化日志）；用量按天聚合入库未做。
- 其他：限速服务自身高可用（当前单实例 + systemd 拉起）。
