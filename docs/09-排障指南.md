# 09 排障指南

按症状查。通用三板斧，先于一切：

1. **启动日志第一条配置摘要**（"服务配置加载完成…"）：受管清单、限额、
   两个配置文件路径——九成"没生效"是这里就能看出的接线错误；
2. **控制台"tc 实况（调试）"面板**：期望配置 vs 内核原始输出摆在一起
   （机器上等价命令：`python3 tools/tc_check.py verify`）；
3. **运行日志**（控制台"日志"页或 journalctl/docker logs）：本项目的
   原则是一切异常大声说中文，错误信息里就写着处置。

## 1. 启动失败类（都是刻意的——宁可起不来，也不要假装在限速）

| 启动报错 | 原因与处置 |
| ---- | ---- |
| `无法创建 IFB 设备 ifbrl0` | 内核缺 ifb 模块（典型：**Docker Desktop** 的精简虚拟机）或容器缺 `CAP_NET_ADMIN`。处置三选一：`RL_TC_IN_MODE=police` 降级（丢包式，实例总闸不可用）；换通用内核的 Linux 主机；确实不需要入向限速设 `RL_TC_IN_IFACE=-` |
| `入向执行网卡的默认值 eth0 在本机不存在` | 机器网卡不是 eth0 命名：设 `RL_TC_IN_IFACE=<客户端侧网卡>`（这一项不做自动探测）；确实不要入向限速设 `RL_TC_IN_IFACE=-` 或删掉 request_limits 段 |
| `客户端侧网卡（RL_TC_IN_IFACE）与后端服务侧网卡（RL_BACKEND_IFACE）都是 X` | 两卡相斥：改正 `/etc/rl-limiter/rl-limiter.env` 里其中一项（或 `install.sh --client-nic/--backend-nic` 重跑）后 restart |
| `RL_TC_IN_MODE=... 不认识` | 只有 `ifb` / `police` 两个值 |
| 容器反复 restart | `docker logs` 看最后几行——上面任意一条的容器表现就是 restart 循环，这是刻意的（`docker ps` 一眼可见不健康） |

## 2. "限速没生效"排查链

1. **tc 实况面板**：期望配置行里有没有这个端口/总闸？
   - 没有 → 配置没到位：quotas（出向目标）和 request_limits（入向
     上限）是两回事；实例环需要
     `instance_quota_mbps` + ifb 模式；
   - 有但原始输出里没有对应 class/filter → 看运行日志里 tc 下发报错；
2. **写 API 改了但没变**：响应是 200 吗？401/403 = 令牌问题；409 =
   实例总限速在本机没有执行者（页面也会置灰并写原因）；400 = 段名
   拼错（错误里列了当前解析到的段名）；
3. **闭环"看起来没在调"**：
   - 配置页看 `dynamic_ingress.enabled` 是否 true 且"闭环在跑"（开着
     但入向未接线时会标注不运行）；
   - 出向观测在死区 [0.85, 1.0]×目标内 → **不动是正常行为**；
   - "采样失联"标签亮着 → degraded 冻结，先修采样（见 §4）；
4. 机器侧核对：`tools/tc_check.py doctor`（环境体检）/`verify`（实况
   与配置比对）。

## 3. 带宽行为异常

**带宽一会高一会低（规律波浪）**：闭环振荡。本分支已把上调改成乘性锚
当前值（+5%×当前值，绝对步长 0.1Mbps），稳态应是"贴着目标线 + 总闸小
台阶"。仍见振荡时：

- 调节视图里看总闸的步幅：一步跳几倍 = 有人把 step_up 语义改回锚上限
  了，别；
- `interval_s` 别小于 5s（观测窗口 10s，调太快是追着噪声跑）；
- 多个外部系统同时在调同一条链路（比如又开了别的限速器）也会互相
  打架。

**压到下限了，出向仍高于目标**：floor 太高。下载型业务 ACK 杠杆
70~150:1，入向均衡点可能只有零点几 Mbps——`floor_ratio` 留低（demo 用
0.05；实例环落位后下限自动锚落位值，一般不会再踩）。

**出向压下来了但客户端报连接慢/超时**：闭环的本性是掐请求方向。先看
是不是目标本身设得太低；再看 conn_rate（SYN 闸）是否误配——它是静态
值，不参与闭环。

**曲线毛刺大**：显示口径本就是 5s 滚动均值；更平滑看 10s 均值那格。
瞬时值（API rate_*）毛刺大是正常的。

## 4. 采样失联（degraded）

页面亮"采样失联"，速率停在陈旧值，超限判定与闭环都冻结。排查：

- 连接统计来源是 /proc/net/snmp（本地文件）：读不到基本只有非 Linux/
  同一路径；
- procfs 未挂载两种可能（容器里缺 /proc 挂载）；
  属组，装机脚本处理过；手工部署查文件属主/mode）；


## 5. 高并发下节点负载异常（demo/压测场景）

- accept 溢出（`netstat -s | grep -i listen` 持续增长）：somaxconn/
  syn_backlog 没到位，见 [08](08-内核参数调优.md)；后端 web 单进程时先
  怀疑后端瓶颈（demo 的 web/loadgen 都已多进程分片，`WEB_PROCS`/
  `LOADGEN_PROCS` 0=自动）；
- loadavg 飙高但 CPU 不满：同机多进程/线程超配（demo 里 WEB_PROCS
  控制业务进程分片数）；
- TIME_WAIT 耗尽（loadgen 侧建连失败）：tw_reuse/端口区间没调。

## 6. 构建与环境

- **Mac/内网构建拉不到 pypi**（`Temporary failure in name resolution`）：
  DNS 被挡，`--build-arg PIP_INDEX_URL=<镜像源>`；
- **Docker Desktop 跑 demo**：ifb 缺失 → 节点启动即失败（见 §1），这
  是内核能力问题不是配置问题；
- **宿主机上残留 tc 规则**（服务异常被杀后）：重启服务即幂等接管；要
  手工清：`tc qdisc del dev <网卡> ingress`、`ip link del ifbrl0`。

安装脚本（`install.sh`）拒绝安装时的报错（都在落盘前，机器不留痕）：

| 报错 | 处置 |
| ---- | ---- |
| `节点要求双网卡……不允许安装` | 物理网卡不足两张（lo/网桥/veth 不算）。节点形态必须双网卡；这台机器只做总控就用 `--fleet` |
| `X网卡 Y 在本机不存在` | 网卡命名不是 eth0/eth1：`--client-nic <客户侧> --backend-nic <后端侧>` 显式指定（`ip -br link` 看名字） |
| `客户侧网卡与后端侧网卡不能是同一张` | 两卡相斥，分别给两张不同的卡；已有 env 里的值也会参与校验 |
| `令牌太短` / `令牌强度不足：……` | 令牌必须是高强度随机串（规则见 [11](11-发布与安装.md) §3.4）：用 `--token auto` 自动生成，或 `openssl rand -hex 32` |
| `查询最新版本失败` / `下载失败` | github.com 不可达，或刚打 tag、附件还没上传完；也可 `--download v<版本>` 钉版本重试 |
| `--client-nic / --backend-nic 只用于节点安装` | 总控（`--fleet`）不碰网卡，去掉这两个选项 |

## 6.5 systemd-networkd 断言崩溃 / 调整限速时网络抖动

症状（生产实例）：限速调整期间宿主机日志出现

```
systemd-networkd: Assertion 'e->key == i->next_key' failed at
src/basic/hashmap.c:..., Aborting.  →  core-dump → 自动重启
```

networkd 重启时按 netplan 重新配置链路，表现为网络瞬时抖动（看起来
像"网卡崩了"；内核里的 tc 规则与数据面本身不受影响）。

根因：networkd 跟踪 rtnetlink 的 TC 对象事件，旧版本在事件风暴下有
迭代中哈希表被并发修改的断言缺陷。rl-limiter 侧的放大器是历史实现里
"层级模式任何差异都整树重建"——闭环每轮调整都产生 qdisc del + 整树
重建的事件风暴。**该放大器已修复**：例行速率变更走 `tc class change`
原位修改（日志应出现"已就地调整 tc 层级限速"，不再每轮"已重建"；
`tc -s class show dev ifbrl0` 的字节计数跨调整持续增长不清零即为证）。

主机侧配套：

1. 升级 systemd（此类断言崩溃在新版本修过多轮）；
2. 让 networkd 不管 IFB 设备，`/etc/systemd/network/10-ifbrl0.network`：

   ```ini
   [Match]
   Name=ifbrl0
   [Link]
   Unmanaged=yes
   ```

3. 确认 netplan 对业务网卡的配置幂等（networkd 重启重配时静态地址
   不闪断，DHCP 接口要留意）。

如仍频繁出现"已重建"日志：说明结构真的在变（端口增删/过滤器丢失），
按 §2 的排查链看 tc 实况面板找原因。
