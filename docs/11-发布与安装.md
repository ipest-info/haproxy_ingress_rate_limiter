# 11 发布与安装（二进制）

目标机**不需要 Python**：发布物是 PyInstaller 单文件二进制
（`rl-limiter` + `rl-fleet`），连同配置模板、安装脚本打成一个 tar.gz。

## 1. 命名规则

| 对象 | 规则 | 示例 |
| ---- | ---- | ---- |
| git tag | `v<主>.<次>.<补丁>`，语义化版本，**必须等于 pyproject.toml 的 version**（CI 校验，不一致构建直接失败）；预发布加 `-rcN` | `v0.4.0`、`v0.5.0-rc1` |
| Release | 与 tag 同名（CI 自动创建，`-rc` 自动标 prerelease） | `v0.4.0` |
| 发布包 | `rl-limiter-<tag>-linux-<架构>.tar.gz` + 同名 `.sha256` | `rl-limiter-v0.4.0-linux-x86_64.tar.gz` |

版本号怎么升：

- **补丁**：修 bug、文案，配置与接线完全兼容；
- **次**：新功能（新页面/新字段/新进程），旧配置原样可用；
- **主**：配置或接线有不兼容变更（启动时会给迁移指引的那种）。

## 2. 发布流程（维护者）

```bash
# 1. 确认 pyproject.toml 的 version 已是要发的号；
# 2. 打 tag 推上去，CI（.github/workflows/release.yml）自动构建发布：
git tag v0.4.0
git push origin v0.4.0
```

CI 在 manylinux2014 容器（glibc 2.17）里构建——**CentOS 7 / RHEL 7
及之后**的发行版都能直接跑产物。本地手工构建（调试用；兼容性只到
构建机同代系统）：

```bash
deploy/release/build.sh        # 产物在 dist/，版本取 pyproject.toml
```

## 3. 安装（运维）

一条命令（下载 + sha256 校验 + 安装）：

```bash
curl -fL -o install.sh https://raw.githubusercontent.com/ipest-info/haproxy_ingress_rate_limiter/main/deploy/release/install.sh
chmod +x install.sh
sudo ./install.sh --download v0.4.0            # 节点
sudo ./install.sh --download v0.4.0 --fleet    # 节点 + 总控单元
```

或者手头已有发布包：

```bash
tar xzf rl-limiter-v0.4.0-linux-x86_64.tar.gz
cd rl-limiter-v0.4.0-linux-x86_64
sudo ./install.sh              # 加 --fleet 连总控一起装
```

装了什么、不动什么：

| 路径 | 行为 |
| ---- | ---- |
| `/usr/local/bin/rl-limiter`、`rl-fleet` | 每次安装**覆盖**（升级就是重跑 install.sh + restart） |
| `/etc/rl-limiter/config.yaml`、`rl-limiter.env`（`--fleet` 时另有 `fleet.yaml`） | 首次从模板生成，已存在**绝不覆盖** |
| `/etc/systemd/system/rl-limiter.service`（`--fleet` 时另有 `rl-fleet.service`） | 每次安装覆盖（权限模型与 venv 装法一致：专用用户 + CAP_NET_ADMIN） |

装完**不自动启动**：先编辑两份配置（接线见 [04 部署指南](04-部署指南.md)），
再 `systemctl enable --now rl-limiter`。

## 4. 二进制装法与 venv 装法（deploy/bare）怎么选

| | 二进制（本篇） | venv（`deploy/bare/rl-limiter.sh`） |
| ---- | ---- | ---- |
| 目标机依赖 | 无（glibc ≥ 2.17 即可） | python3 ≥ 3.9 |
| 升级 | 重跑 install.sh | 重跑装机脚本 |
| 适用 | 批量生产机、离线环境 | 开发机、想直接读改源码的环境 |

两种装法的配置路径、systemd 权限模型完全相同，可互相切换（配置不动，
换掉执行体即可）。
