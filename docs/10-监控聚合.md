# hap-agg：多台 HAProxy 的监控聚合

适用场景：机器上已经有一批 HAProxy 在跑（不管有没有装 rl-limiter），
想要**一个页面看全所有实例**——总带宽、总连接、每台的健康状况、同名
frontend 跨机合并的吞吐。

一句话：在任意一台能到达各 HAProxy 内网 9999 端口的机器上跑
`hap-agg -c agg.yaml`，浏览器打开 `http://127.0.0.1:8100`。

与 rl-limiter 的关系：**共用仓库与安装包，定位互补**。rl-limiter 与
HAProxy 同机、做限速 + 单机监控；hap-agg 是纯只读的跨机聚合观测，
目标机器**不需要装任何东西**。两者可同时使用，互不依赖。

---

## 1. 前提：目标机器暴露内网 TCP stats socket

每台被聚合的 HAProxy，haproxy.cfg 的 `global` 段要有一条内网 TCP
stats socket：

```
stats socket ipv4@<内网IP>:9999 level user
```

- **level user 就够**——hap-agg 只执行 `show stat` / `show info` 两条
  只读命令。已有的 `level admin expose-fd listeners` socket 也能用
  （那是给 seamless reload 用的），但要清楚：**admin 级 socket 绑到
  0.0.0.0 等于把 HAProxy 的管理权（改权重、下线服务器、关进程）暴露给
  全内网**。强烈建议绑内网 IP 并用防火墙/安全组限制来源；
- 改完 `systemctl reload haproxy` 即生效，无需重启。

## 2. 配置与启动

```bash
cp deploy/config/hap-agg.example.yaml /etc/hap-agg/config.yaml
# 编辑 targets 列表，然后：
hap-agg -c /etc/hap-agg/config.yaml --port 8100
```

配置就四个字段：

```yaml
log_level: info
poll_interval_s: 1.0     # 采样节拍（秒），0.2-60
timeout_ms: 500          # 单目标单命令超时
targets:
  - 10.0.0.11:9999       # 名字缺省 = 地址
  - name: sg-02          # 显式命名
    addr: 10.0.0.12:9999
```

`--bind` 默认 `127.0.0.1`：读接口无鉴权，放内网必须显式指定并配防火墙。

## 3. 批量导入（页面 / API）

目标清单可以在运行期批量导入，不用改文件重启：

- **页面**：底部"批量导入目标"卡，每行一条 `IP:port` 或
  `名字 IP:port`（`#` 为注释），需在页头填 API 令牌（服务端环境变量
  `RL_API_TOKEN`，与 rl-limiter 写 API 同一套约定，未配置则写接口
  整体 403）；
- **API**：

  ```bash
  curl -X POST -H "X-API-Token: $TOKEN" -H "Content-Type: application/json" \
       -d '{"text": "10.0.0.11:9999\nsg-02 10.0.0.12:9999"}' \
       http://127.0.0.1:8100/api/targets
  curl -X DELETE -H "X-API-Token: $TOKEN" \
       http://127.0.0.1:8100/api/targets/sg-02
  ```

导入规则：**一行错整批拒绝**（半批导入比报错难收拾）；同名同址幂等
跳过，同名异址明确拒绝（静默替换会让人以为旧地址还在被监控）；结果
立即生效（下一拍开始采样）并**回写 YAML**（原子替换，手写注释会丢）。
手工编辑 YAML 则要重启才生效——运行态以进程内存为准，双写入口才需要
合并逻辑，这里刻意不做。

## 4. 视图与口径

页面四块（数据同源，也全部可经 JSON API / SSE / Prometheus 取用）：

| 视图 | 内容 | 来源 |
| --- | --- | --- |
| 聚合总览 | 流入/流出带宽、整机并发合计、frontend 并发合计、每秒新建/拒绝、连接上限合计 + 三张实时曲线 | 全部**健康**目标之和 |
| 实例列表 | 每台一行：状态（正常/抖动/失联+原因）、并发、带宽、新建/拒绝、空闲率、运行时长 | `show info` + Σ frontend |
| frontend 聚合 | 同名 frontend 跨机合并（水平扩容形态）：实例数、并发、带宽、新建/拒绝 | 各目标 `show stat` 的 FRONTEND 行 |
| 目标管理 | 批量导入 / 删除 | —— |

口径要点：

- 速率一律**应用层 bytes/s**（HAProxy 计数器差分，与 rl-limiter 的
  监控口径一致），页面显示换算成 Mbps；
- HAProxy reload 会清零计数器：负差分按 0 处理，曲线出现一拍空洞后
  自动恢复——比一根荒谬的负速率曲线诚实；
- 单目标失败不影响其它目标；连续 3 拍失败标记**失联**，其行保留在
  实例列表里（带错误原因与最近一次成功的陈旧数字），但**不计入聚合
  合计**——陈旧速率混进总数会让总带宽虚高且无从发现；
- "整机并发"（`show info` 的 CurrConns，含 stats socket 自身等全部
  连接）与"frontend 并发"（Σ 各 frontend scur）口径不同，两个都给。

## 5. 接口

与 rl-limiter 控制台同一套形态（详见 [07-API文档.md](07-API文档.md)
的通用约定；hap-agg 的端点独立、更少）：

| 端点 | 说明 |
| --- | --- |
| `GET /api/overview` | 服务信息 + 目标清单 + 最新一拍快照 |
| `GET /api/history` | 最近约 10 分钟快照（内存，重启清空） |
| `GET /api/stream` | SSE：每拍推一帧快照 |
| `GET /metrics` | Prometheus 文本格式：`hap_agg_total_*`（聚合）、`hap_agg_target_*{target,addr}`（每台，含 `hap_agg_target_up`）、`hap_agg_frontend_*{frontend}`（跨机合并） |
| `POST /api/targets` | 批量导入（令牌鉴权），见 §3 |
| `DELETE /api/targets/{name}` | 删除目标（令牌鉴权） |

## 6. 没做的部分

- **没有 per-server/backend 维度**。当前采集 frontend 行 + 进程级
  指标——那是"入口带宽/连接"这个主题的全部；backend/server 健康检查
  的可视化是另一个话题（HAProxy 自带 stats 页面就有），先不重复造；
- **没有持久化历史**。内存只留 10 分钟，长期历史接 Prometheus 抓
  `/metrics`；
- **没有 systemd 装机脚本**。`hap-agg` 是单文件配置的纯用户态进程，
  照 docs/09 的 unit 模板抄一份、去掉 CAP_NET_ADMIN 即可。
