# 06 控制台与监控

设 `RL_CONSOLE_PORT` 即启用内置 Web 控制台（默认只绑 `127.0.0.1`；
读接口无鉴权，放内网前先看 §6 安全边界）。同端口还提供 Prometheus
`/metrics` 与全套 JSON API（见 [07 API 参考](07-API参考.md)）。

数据链路：监控循环每秒采样一拍 → StatusHub 合成快照 → 页面经 SSE 实时
收帧；两级视图（实例/监听端口）出自同一拍，切页时间轴对齐。

## 1. 读数口径（每张图都标了来源，数值本就不该相等）

| 来源 | 口径 | 用在 |
| ---- | ---- | ---- |
| HAProxy stats | 应用层字节，按 frontend 精确拆分 | 带宽曲线、超限判定、闭环观测 |
| tc 队列 | 链路层字节 + 包/丢包，按 frontend 拆分（仅出向 HTB 形态） | 端口的数据包与丢包图 |
| 网卡（/proc/net/dev） | 链路层、整机范围 | 实例面板的**设备视图**：每张受监控网卡一块带宽图 + 逐卡数据包/丢包曲线（`RL_NIC` 选卡，逗号分隔多张；默认 = 本机全部物理网卡，双网卡机器 eth0/eth1 都在） |

**实时带宽的显示口径是 5 秒滚动均值**：1s 差分的瞬时值毛刺太大（短连接
场景尤甚）。只影响显示——告警/承诺口径仍是 10s 均值（页面上"10s 均值"
那格），API 的 `rate_*` 字段仍是瞬时值。

## 2. 实例页

- **总览**：并发/活跃/新建/丢失连接、流入流出带宽（5s 均值）、连接
  上限、HAProxy 空闲率；采样失联时亮"采样失联"标签；
- **实例总限速**：填的是**实例出向总带宽目标**（Mbps，0=不限）。本机
  没有执行者时（出向 tc 关 + 非 ifb 模式）卡片置灰并明示原因，写接口
  同步 409；
- **连接视图 / 设备视图**：实例级曲线——连接（新建/总连接）按 HAProxy
  口径；带宽/数据包/丢包**按设备（网卡）**逐卡成块（双网卡两块带宽图，
  网卡集合变化页面自动重建；没有网卡数据源时带宽回退 HAProxy 口径）；
- **调节视图（闭环动态限速）**：闭环没在工作时隐藏。调节相关的数据
  全摆在一处（单位一律 Mbps）：
  - 指标条：实例出向目标 / 出向总观测（10s 均值，控制环观测值）/
    入向总闸当前值（全开时标上限）/ 实测流入 / 调节状态（等落位、
    已落位调节中、全开）；
  - 三张曲线：**出向总带宽 vs 目标参考线**（看收敛与平稳）、**入向
    总闸与实测流入**（看执行值每一步落在流入的哪个刻度）、**网卡带宽**
    （链路层整机口径）；
  - 按端口表格：每个受调端口的出向目标/观测、入向动态上限/登记上限/
    状态。
  判读：收敛好 = 出向贴着目标线、总闸是小台阶；大锯齿/规律波动 =
  振荡，见 [09 排障指南](09-排障指南.md)；
- **tc 实况（调试）**：期望配置与内核 `tc ... show` 原始输出摆在一起，
  每段带"怎么读"的折叠说明；动态值会标出来（如
  `实例出向目标=40Mbps→入向总闸 0.6Mbps（动态）`）。不自动轮询，手动
  刷新。

## 3. 监听端口页

每个 frontend 一张卡：

- 指标条：实时下行（5s 均值）、10s 均值、限额、利用率、并发、活跃/
  非活跃；持续超限时亮"超限"标签；
- 四张曲线：新建/丢失连接、总连接、带宽（含流出 10s 均值与限额参考
  线）、数据包与丢包（tc 队列口径，出向 HTB 形态才有数据）；
- 右上角可直接改该端口的 `quotas` 限额（0=显式不限；删除登记=回到只
  监控）。

## 4. 配置页

把"能改的"与"只能看的"分开摆（详见 [03 配置参考](03-配置参考.md)）：

- **限额登记（可改，热生效）**：实例总限速 + 各端口 quotas；
- **入向限速登记 request_limits（可改，热生效）**：每端口两个输入框
  （入向带宽上限 / 每秒新建连接），**各自独立保存**；入向未接线时置灰
  并说明原因；
- **运行参数（启动时定型，只读）**：YAML/cfg 路径、stats 接口、采样
  周期、log_level、出入向网卡与执行模式、落盘与令牌状态；
- **入向动态限速 dynamic_ingress（只读）**：闭环参数当前生效值。

页面对结构零假设（服务端下发 section 清单，可编辑字段带着自己的写 API
描述）——这也是三条形态分支共用同一份前端的原因。

## 5. 告警、落盘与 Prometheus

- **持续超限告警**（loop.py）：mean10 连续高于限额 **10s** 才告警
  （瞬时冲高不告），回落同样持续 10s 才解除——两侧滞回防临界抖动；
  告警期间每 **300s** 重复提醒一次防配置漂移被淹没。采样失联期间判定
  冻结。告警落在运行日志（页面"日志"页可看，带级别过滤）；
- **监控数据落盘**：设 `RL_METRICS_LOG` 启用。每自然分钟聚合一行
  JSONL（每 frontend 一行 + 实例一行），按天轮转，默认保留 90 天
  （`RL_METRICS_LOG_DAYS`）。历史回查/计费对账用它，写失败不影响监控
  主链路；
- **`/metrics`**：Prometheus 文本格式，与控制台同源同口径（速率一律
  bytes/s 应用层）。全部是 gauge；服务刚起还没采到第一拍时只输出服务
  级指标——空值比编造的 0 诚实。

## 6. 安全边界

- 读接口（页面、/api/*、/metrics）**无鉴权**，且默认绑 0.0.0.0（监控
  页内网直达）：**必须**用防火墙/安全组限制来源，绝不可暴露公网；绑非
  回环时日志会 warning 留痕，只想本机访问设 `RL_CONSOLE_BIND=127.0.0.1`；
- 写接口（改限额）必须带令牌（`RL_API_TOKEN`，页头输入后随写请求头
  发送、存 localStorage）；未配置令牌时写接口整体 403、页面只读；
- 页面所有外部文本（配置名、tc 输出、错误信息）渲染前统一转义——
  控制台没有任何把外部数据拼进 HTML 的缝。
