# 10 总控制台（rl-fleet）：多机总量控制

一台总控管数十台节点：汇总查看全部 HAProxy 的流量，并把**总流出带宽**
按需动态分配为各节点的实例出向目标——节点自己的闭环再把出向目标转成
入向限速（见 [02 闭环限速原理](02-闭环限速原理.md)），总量约束就此达成。

## 1. 架构

```
                 ┌───────────── rl-fleet（总控，独立进程）─────────────┐
                 │ 轮询环(2s)：GET 各节点 /api/overview → 汇总观测/页面 │
                 │ 分配环(15s)：total 按需切分 → PUT /api/instance-quota│
                 └───────┬───────────────┬───────────────┬────────────┘
                         ▼               ▼               ▼
                  node1 rl-limiter  node2 rl-limiter  node3 …（数十台）
                  实例出向目标 → 各自闭环 → 各自的入向总闸（IFB/HTB）
```

关键设计：

- **节点侧零改动**。总控只是节点控制台 API 的一个客户端：轮询
  `/api/overview`，下发 `PUT /api/instance-quota`（节点令牌鉴权）。
  节点上生效的就是页面上手工设"实例总限速"的同一条路径——回写节点
  YAML、热生效、重启不丢；
- **双环分工**：总控是慢速外环（默认 15s 一轮，只动各节点的出向
  目标），节点闭环是快速内环（把目标转成入向限速）。外环刻意慢于
  内环的收敛时间，两环不打架；
- **观测同口径（网卡）**：总控用的出向观测 = 节点闭环自己的观测
  （`regulation.instance.egress_mbps`，即节点客户端侧网卡的流出 10s
  均值——与按量计费同口径）；节点还没在调时退网卡瞬时差分
  （`nic_rate_out_bytes_per_s`），连设备数据都没有（节点 `RL_NIC=-`）
  才退 HAProxy 应用层口径求和——分配不追瞬时毛刺、不参考应用层字节；
- **无数据库**：总控的全部配置在一份 fleet YAML 里（节点清单 + 总带宽
  + 分配参数），轮询热生效；页面改总带宽 = 写 API 回写该文件。

## 2. 部署与配置

```bash
rl-fleet -c /etc/rl-limiter/fleet.yaml
# 环境变量（与节点侧同名同义）：
#   RL_CONSOLE_PORT=8095     控制台端口（不设 = 无页面，纯后台分配）
#   RL_CONSOLE_BIND=0.0.0.0  （默认；读接口无鉴权，防火墙限源）
#   RL_API_TOKEN=<总控自己的写令牌，页面改总带宽用>
```

fleet YAML 全字段见 `deploy/config/fleet.example.yaml`（带注释的生产
示例）。核心段：

```yaml
total_egress_mbps: 1000     # 热更；0 = 纯观察不下发
alloc_interval_s: 15        # 分配周期（≥10，启动定型）
allocation: { min_share_ratio: 0.2, ... }   # 分配参数，热更
nodes:
  - name: node-sh-01
    url: http://10.0.1.11:8090      # 节点控制台（内网）
    token: <该节点的 RL_API_TOKEN>
```

节点侧前提（每台）：`RL_CONSOLE_BIND` 绑总控可达的内网地址（读接口无
鉴权，务必用防火墙/安全组限制只有总控能访问）+ `RL_API_TOKEN` 设令牌。

## 3. 分配算法（按需动态）

每个分配周期（默认 15s）：

1. **分组**：可控节点 = 在线 + 实例限速可执行 + 未降级 + 有令牌；
   其余为**冻结**组；
2. **冻结记账**：冻结节点的配额**绝不碰**（fail-static——失联时乱动
   它的配额是大忌），但它占着的份额如实从可分池里扣掉：
   `池 = total − Σ冻结配额`。冻结之和超过 total 时告警"超卖"，可控
   节点被压到保底；
3. **需求信号**：节点近期出向（10s 均值）再过一层 EWMA 平滑；**被
   自己配额压着的节点**（出向 ≥ 0.9×配额）按 `配额×1.3` 虚报——它的
   真实需求被配额挡住了观测，不虚报会陷入"配额小→观测小→分得更小"
   的饿死锁定，虚报让它逐轮长大、自然收敛；
4. **保底 + 按需比例**：每个可控节点保底 `min_share_ratio×池/N`，
   剩余按需求占比瓜分。恒等式：**Σ分配 + 冻结记账 = total**（页面
   "已分配合计"偏离总带宽超 2% 会标黄）；
5. **下限与写抑制**：分配值永远 ≥ `min_quota_mbps`（绝不下发 ≤0——
   0 在节点语义是"不限"）；与节点现值差距 < max(5%, 1Mbps) 不下发
   （节点每次写都整份重写自己的 YAML，琐碎变化不值得）。

边界语义速查：

| 场景 | 行为 |
| ---- | ---- |
| 节点离线/采样降级 | 配额冻结 + 记账扣池；恢复后需求均值重置、自动纳回 |
| 实例限速不可执行（executable=false） | 永久冻结组，绝不下发（省掉必然的 409） |
| 全体空闲 | 可分池均分（任何节点来流量都立刻有承接额度），写抑制保证不抖 |
| 新节点入清单 | 首次轮询成功前不参与分配（没有观测不乱动） |
| 节点移出清单 | 停止轮询与下发，配额**不回收不清零**（移除 ≠ 释放），WARN 留痕 |
| 节点上有人手工改配额 | WARN 点名 + 下轮按分配覆盖——总控是 instance_quota 的权威；要豁免某台就把它移出清单 |
| 下发 401/403 | 记在节点表"最近错误"列 + ERROR 处置提示（核对两边令牌），下轮自然重试 |

## 4. 总控页面与 API

页面（`RL_CONSOLE_PORT`）：总量控制卡（总带宽编辑 + 三张曲线：总出向
vs 总带宽参考线 / 总入向 / 在线节点数）+ 节点表（状态徽标、出向/入向、
配额与本轮分配、利用率条、最近错误、点名称跳该节点自己的控制台）。
**总出向曲线被压在虚线之下，就是总量控制在生效的现场证据。**

API（口径与节点侧一致，读无鉴权、写要令牌）：

| 路由 | 说明 |
| ---- | ---- |
| `GET /api/overview` | 总控视图：total、分配参数、latest 快照 |
| `GET /api/history` / `GET /api/stream` | 快照历史 / SSE 实时流 |
| `PUT /api/total-quota` | `{"quota_mbps": n}`，回写 fleet YAML 热生效 |
| `DELETE /api/total-quota` | 置 0 = 停止分配（纯观察，各节点保持现状） |

快照里的 `nodes.*` 字段：`online/degraded/executable/egress_mbps/
ingress_mbps/quota_mbps(节点自报)/desired_mbps(本轮分配)/util/error/
write_err`。节点令牌绝不出现在任何读接口里。

## 5. demo 玩法

```bash
make demo-up                  # 三节点 + 总控（http://localhost:8095）
# 页头填令牌 demo-token → 总量控制卡设 90（Mbps）
curl -X PUT localhost:8084/concurrency -d '{"concurrency": 900}'   # 加压
```

预期看到：三节点配额先均分起步，谁流量大谁的配额逐轮长大（此消彼长）；
总出向约 1 分钟收敛到 90 的参考线下并稳住；停掉一台节点
（`docker stop *_node2_1`）后它在表里变"离线"、配额被冻结记账，其余
两台分走剩余池；重启后自动纳回。

## 6. 排障

- **节点一直"离线"**：总控容器/机器到节点 `url` 的连通性（节点默认绑
  0.0.0.0，若被改回 127.0.0.1 则只有本机能访问）；
- **节点表"最近错误"列有 401/403**：fleet.yaml 里该节点 token 与节点
  `RL_API_TOKEN` 不一致；
- **"已分配合计"标黄**：有冻结节点在记账占份额（正常，处理掉离线/
  降级节点即恢复），或冻结之和已超总带宽（超卖告警，日志里有明细）；
- **总出向压不到总带宽**：看是哪台节点超——节点表利用率 >100% 的那台
  的内环没收敛，跳到它自己的控制台看"调节视图"（参照
  [09 排障指南](09-排障指南.md) §3）；
- **改了总带宽没反应**：写 API 返回 200 了吗（令牌）？下发在**下一个
  分配周期**（默认 15s）执行，节点生效还要再等它自己的内环走几轮。
