# 10 总控制台（rl-fleet）：多机总量控制

一台总控管数十台节点：汇总查看全部服务器的流量（网卡口径），并把**总流出带宽**
按需动态分配为各节点的实例出向目标——节点自己的闭环再把出向目标转成
入向限速（见 [02 闭环限速原理](02-闭环限速原理.md)），总量约束就此达成。

## 1. 架构

```
                 ┌───────────── rl-fleet（总控，独立进程）─────────────┐
                 │ 轮询环(2s)：GET 各节点 /api/overview → 汇总观测/页面 │
                 │ 分配环(15s)：total 按需切分 → PUT /api/instance-quota│
                 └───────┬───────────────┬───────────────┬────────────┘
                         ▼               ▼               ▼
                  node1 rl-limiter  node2 rl-limiter  node3 …（数十台）
                  实例出向目标 → 各自闭环 → 各自的入向总闸（IFB/HTB）
```

关键设计：

- **节点侧零改动**。总控只是节点控制台 API 的一个客户端：轮询
  `/api/overview`，下发 `PUT /api/instance-quota`（节点令牌鉴权）。
  节点上生效的就是页面上手工设"实例总限速"的同一条路径——回写节点
  YAML、热生效、重启不丢；
- **双环分工**：总控是慢速外环（默认 15s 一轮，只动各节点的出向
  目标），节点闭环是快速内环（把目标转成入向限速）。外环刻意慢于
  内环的收敛时间，两环不打架；
- **观测同口径（网卡）**：总控用的出向观测 = 节点闭环自己的观测
  （`regulation.instance.egress_mbps`，即节点客户端侧网卡的流出 10s
  均值——与按量计费同口径）；节点还没在调时退网卡瞬时差分
  （`nic_rate_out_bytes_per_s`），连设备数据都没有（节点 `RL_NIC=-`）
  才退 HAProxy 应用层口径求和——分配不追瞬时毛刺、不参考应用层字节；
- **无数据库**：总控的全部配置在一份 fleet YAML 里（节点清单 + 总带宽
  + 分配参数），轮询热生效；页面改总带宽、「节点管理」增删改节点 =
  写 API 回写该文件。

## 2. 部署与配置

二进制安装（见 [11 发布与安装](11-发布与安装.md) §3.2）：

```bash
sudo ./install.sh --download --fleet --token auto     # 自动生成高强度令牌，装完打印
sudo systemctl enable --now rl-fleet
# 打开 http://<总控>:8095 → 页头填总控令牌 →「节点管理」逐台添加节点
```

`--fleet` 只装总控、不查网卡；`--token` 写进
`/etc/rl-limiter/rl-fleet.env`。手工运行等价于：

```bash
rl-fleet -c /etc/rl-limiter/fleet.yaml
# 环境变量（与节点侧同名同义；模板 deploy/config/rl-fleet.env.example）：
#   RL_CONSOLE_PORT=8095     控制台端口（不设 = 无页面，纯后台分配）
#   RL_CONSOLE_BIND=0.0.0.0  （默认；读接口无鉴权，防火墙限源）
#   RL_API_TOKEN=<总控自己的写令牌，页面改总带宽、增删节点用；
#                 高强度随机串，不达标当作未设，见 docs/11 §3.4>
#   RL_METRICS_LOG=/var/log/rl-limiter/fleet-metrics.jsonl
#                            监控落盘（不设 = 不落盘，没法事后反查；见 §5）
#   RL_METRICS_LOG_DAYS=90   落盘保留天数
```

fleet YAML 全字段见 `deploy/config/fleet.example.yaml`（带注释的生产
示例；出厂为空节点清单）。核心段：

```yaml
total_egress_mbps: 1000     # 热更；0 = 不做总量控制（从 >0 改 0 时解除各节点限速）
alloc_interval_s: 15        # 分配周期（≥10，启动定型）
allocation: { min_share_ratio: 0.2, ... }   # 分配参数，热更
nodes:
  - name: node-sh-01
    url: http://10.0.1.11:8090      # 节点控制台（内网）
    token: <该节点的 RL_API_TOKEN>
```

节点清单三种维护方式，效果相同（都是改这份 YAML、热生效）：

- **粘贴接入串**（推荐，可批量）：节点装完 `install.sh` 会单独打印一行

  ```
  rl-node name=node-sh-01 url=http://10.0.1.11:8090 token=<该节点令牌>
  ```

  把它（多台就攒成多行，整段安装输出直接粘也行）粘进「节点管理」→
  「粘贴接入串」：粘完自动预览每行的结果——**新增** / **更新**（同名节点
  的地址或令牌变了，如节点 `--token auto` 重跑过）/ **无变化** / **有错**
  （缺字段、名称/地址非法、令牌强度不足、同一批里重名），确认后点「导入
  N 台」一次原子写入；有错的行跳过并留在框里待改。接入串没带 token =
  该节点只读观测（更新时会清掉总控里的旧令牌——节点已经没有令牌，留着
  只会一直 401）。地址默认是节点**后端侧网卡**的 IPv4 + 控制台端口，
  名称默认短主机名，装节点时可用 `--advertise` / `--node-name` 改；
  事后在节点上 `sudo ./install.sh --show-join` 补打；
- **页面「节点管理」手工添加**：填名称、节点控制台地址、该节点令牌（、
  可选的页面跳转地址）即添加；已登记节点可编辑（名称不可改——改名 =
  删了重加；令牌留空 = 保持原值，可勾选清除转只读观测）、删除。需页头
  填总控令牌。重名添加会被拒绝（409），不会覆盖已登记节点；节点令牌
  必须过强度规则（[11](11-发布与安装.md) §3.4），弱令牌 400 拒收；
  手写进 YAML 的弱令牌加载时作废（该节点只读观测，页面标"强度不足 ·
  已作废"）；
- **直接编辑 YAML 的 nodes 段**：5s 内热生效。

接入串格式（一行一台，空格分隔 key=value，`rl-node ` 之前的内容与不含它
的行忽略）：`rl-node name=<名称> url=<节点控制台地址> [token=<令牌>]
[console=<页面跳转地址>]`。

节点侧前提（每台）：`RL_CONSOLE_BIND` 绑总控可达的内网地址（读接口无
鉴权，务必用防火墙/安全组限制只有总控能访问）+ `RL_API_TOKEN` 设令牌
（装节点时 `install.sh --token auto` 生成，已包含在接入串里）。

## 3. 分配算法（按需动态）

每个分配周期（默认 15s）：

1. **分组**：可控节点 = 在线 + 实例限速可执行 + 未降级 + 有令牌；
   其余为**冻结**组；
2. **冻结记账**：冻结节点的配额**绝不碰**（fail-static——失联时乱动
   它的配额是大忌），但它占着的份额如实从可分池里扣掉：
   `池 = total − Σ冻结配额`。冻结之和超过 total 时告警"超卖"，可控
   节点被压到保底；
3. **需求信号**：节点近期出向（10s 均值）再过一层 EWMA 平滑；**被
   自己配额压着的节点**（出向 ≥ 0.9×配额）按 `配额×1.3` 虚报——它的
   真实需求被配额挡住了观测，不虚报会陷入"配额小→观测小→分得更小"
   的饿死锁定，虚报让它逐轮长大、自然收敛；
4. **保底 + 按需比例**：每个可控节点保底 `min_share_ratio×池/N`，
   剩余按需求占比瓜分。恒等式：**Σ分配 + 冻结记账 = total**（页面
   "已分配合计"偏离总带宽超 2% 会标黄）；
5. **下限与写抑制**：分配值永远 ≥ `min_quota_mbps`（绝不下发 ≤0——
   0 在节点语义是"不限"）；与节点现值差距 < max(5%, 1Mbps) 不下发
   （节点每次写都整份重写自己的 YAML，琐碎变化不值得）。

边界语义速查：

| 场景 | 行为 |
| ---- | ---- |
| 节点离线/采样降级 | 配额冻结 + 记账扣池；恢复后需求均值重置、自动纳回 |
| 实例限速不可执行（executable=false） | 永久冻结组，绝不下发（省掉必然的 409） |
| 全体空闲 | 可分池均分（任何节点来流量都立刻有承接额度），写抑制保证不抖 |
| 新节点入清单 | 首次轮询成功前不参与分配（没有观测不乱动） |
| 节点移出清单 | 停止轮询与下发，配额**不回收不清零**（移除 ≠ 释放），WARN 留痕 |
| 取消总量控制（total 从 >0 改为 0：页面按钮、API 或改 YAML） | **立即**向每台有令牌的节点 `DELETE /api/instance-quota`，节点恢复不限；离线/下发失败的标"待解除"，每轮重试、恢复在线即解；重新设了总带宽则作废。之后总控只汇总、不再碰节点 |
| 总控以 total=0 启动 | 不碰节点（不知道节点上的限速是谁设的）；运行中设了总带宽再取消才会解除 |
| 改总带宽 | 立即跑一轮分配（不等分配周期） |
| 节点上有人手工改配额 | WARN 点名 + 下轮按分配覆盖——总控是 instance_quota 的权威；要豁免某台就把它移出清单 |
| 下发 401/403 | 记在节点表"最近错误"列 + ERROR 处置提示（核对两边令牌），下轮自然重试 |

## 4. 总控页面与 API

页面（`RL_CONSOLE_PORT`）四个页签：

- **总览**：总量控制卡（总带宽编辑 + 三张曲线：总出向 vs 总带宽参考线 /
  总入向 / 在线节点数）+ 节点表（状态徽标、出向/入向、配额与本轮分配、
  利用率条、最近错误、点名称跳该节点自己的控制台）；
- **节点管理**：添加节点表单 + 已登记节点列表（地址、令牌有无、实时
  状态、编辑/删除）；
- **历史回查**：读监控落盘（§5）——选时间范围（最近 1 小时/6 小时/
  24 小时/7 天或自定义）与对象（全部节点汇总或单个节点），看分钟级曲线
  （出向均值/峰值 + 当时生效的总带宽目标或节点配额，阶梯虚线）、区间
  摘要（峰值、均值、超出总带宽的分钟数、配额范围）与限速变更事件表，
  可下载该次查询的原始 JSONL；
- **日志**（进程内最近 1000 条，重启即清；历史看 journalctl）。

**总出向曲线被压在虚线之下，就是总量控制在生效的现场证据。**

API（口径与节点侧一致，读无鉴权、写要令牌）：

| 路由 | 说明 |
| ---- | ---- |
| `GET /api/overview` | 总控视图：total、分配参数、latest 快照 |
| `GET /api/history` / `GET /api/stream` | 快照历史 / SSE 实时流 |
| `PUT /api/total-quota` | `{"quota_mbps": n}`，回写 fleet YAML 热生效 |
| `DELETE /api/total-quota` | 置 0 = 取消总量控制：立即解除各节点的实例总限速（恢复不限），之后只汇总不下发 |
| `GET /api/nodes` | 节点清单：`name/url/console_url/has_token`（令牌只给有无） |
| `POST /api/nodes` | 添加节点 `{"name", "url", "token"?, "console_url"?}`；重名 409 |
| `POST /api/nodes/import` | 粘贴接入串批量导入 `{"text": "<一行一台>", "dry_run": true\|false}`：返回每行 `action`（add/update/same/error）与原因、各类计数；`dry_run` 只预览不写盘，正式导入跳过有错的行、其余一次原子回写。不回显令牌 |
| `PUT /api/nodes/{name}` | 改 `url/token/console_url` 中给出的字段（`token: ""` = 清除）；不存在 404 |
| `DELETE /api/nodes/{name}` | 删除节点（停止轮询与下发，其配额保持现状）；不存在 404 |
| `GET /api/metrics-log` | 反查监控落盘（§5）；未启用落盘时 404 |

写接口一律 `X-API-Token: <总控令牌>`（或 `Authorization: Bearer`），
未配置总控令牌时整体 403。例：

```bash
curl -X POST http://127.0.0.1:8095/api/nodes -H 'X-API-Token: <总控令牌>' \
  -d '{"name": "node-sh-03", "url": "http://10.0.1.13:8090", "token": "<节点令牌>"}'
```

快照里的 `nodes.*` 字段：`online/degraded/executable/egress_mbps/
ingress_mbps/quota_mbps(节点自报)/desired_mbps(本轮分配)/util/error/
write_err`。节点令牌绝不出现在任何读接口里。

## 5. 监控落盘与反查

设了 `RL_METRICS_LOG`（`install.sh --fleet` 装出来默认开，路径
`/var/log/rl-limiter/fleet-metrics.jsonl`），总控把看到的一切按**分钟**
追加到这个 JSONL 文件：重启不丢、每天 UTC 零点轮转（旧文件追加
`.YYYY-MM-DD` 后缀）、默认保留 90 天。单位一律 **Mbps**（节点侧的
`metrics.jsonl` 是 bytes/s，对照时注意换算）。三种行用 `kind` 区分：

| kind | 何时写 | 字段 |
| ---- | ---- | ---- |
| `fleet` | 每分钟一行 | `total_mbps`（**当时的**总带宽目标，0 = 未做总量控制）、`egress_avg/max`、`ingress_avg/max`（Σ在线节点）、`allocated_mbps`、`nodes_online_min`、`nodes_total`、`over_samples`（该分钟总出向高于目标的采样次数）、`samples` |
| `node` | 每节点每分钟一行 | `name`、`egress_avg/max`、`ingress_avg/max`（只计在线采样；整分钟离线为 null）、`quota_mbps`（节点自报，0 = 不限）、`desired_mbps`（本轮分配）、`online_samples/samples`、`release_pending`、`error`、`write_err` |
| `event` | 发生即写（ts 精确到秒） | `type` 见下 |

事件 `type`（令牌的值绝不落盘）：

| type | 含义与字段 |
| ---- | ---- |
| `start` | 总控启动：`version`、`total_mbps`、`nodes` |
| `total` | 总带宽变更（页面/API/改 YAML 都算）：`from_mbps` → `to_mbps`（0 = 取消总量控制） |
| `quota` | 给节点下发实例配额成功：`node`、`from_mbps`（下发前自报）→ `to_mbps` |
| `release` | 解除节点的实例总限速成功：`node`、`from_mbps` → 0（不限） |
| `nodes` | 节点清单增删改：`added`（name/url/has_token）、`removed`、`changed`（name + 改了哪些字段） |

反查三种方式：

- **页面**「历史回查」页签（§4）；
- **API** `GET /api/metrics-log`（读接口，无鉴权）：

  | 参数 | 说明 |
  | ---- | ---- |
  | `from` / `to` | unix 秒或 ISO 8601（如 `2026-10-27T08:00:00+08:00`；不带时区按总控本机时区）；缺省 = 最近 1 小时 |
  | `kind` | `fleet,node,event` 的任意组合，缺省全要 |
  | `node` | 只看该节点：node 行只留它，event 行留它的与全局的（总带宽变更、启动） |
  | `limit` | 返回行数上限（默认 20000，最大 50000；超了 `truncated: true`） |
  | `format=jsonl` | 以文件下载原始行 |

  ```bash
  # 昨天 20 点到 22 点，node-sh-01 的分钟数据与相关事件
  curl -s 'http://127.0.0.1:8095/api/metrics-log?from=2026-10-26T20:00:00%2B08:00&to=2026-10-26T22:00:00%2B08:00&node=node-sh-01'
  ```

- **直接查文件**（总控机上，jq）：

  ```bash
  F=/var/log/rl-limiter/fleet-metrics.jsonl
  # 所有总带宽变更与解除限速，带本地时间
  cat $F.* $F 2>/dev/null | jq -c 'select(.kind=="event" and (.type=="total" or .type=="release"))
      | .t=(.ts|localtime|strftime("%F %T"))'
  # 某节点配额的每次变化
  cat $F | jq -c 'select(.type=="quota" and .node=="node-sh-01") | [(.ts|localtime|strftime("%F %T")), .from_mbps, .to_mbps]'
  # 总出向超过总带宽目标的分钟
  cat $F | jq -c 'select(.kind=="fleet" and .over_samples>0) | [(.ts|localtime|strftime("%F %R")), .total_mbps, .egress_max]'
  ```

体量：1 行约 200 字节 ×（节点数 + 1）× 1440 分钟/天——30 台节点一天约
9 MB，保留 90 天约 800 MB。

## 6. demo 玩法

```bash
make demo-up                  # 三节点 + 总控（http://localhost:8095）
# 页头填演示令牌（见 docs/05 §1）→ 总量控制卡设 90（Mbps）
curl -X PUT localhost:8084/concurrency -d '{"concurrency": 900}'   # 加压
```

预期看到：三节点配额先均分起步，谁流量大谁的配额逐轮长大（此消彼长）；
总出向约 1 分钟收敛到 90 的参考线下并稳住；停掉一台节点
（`docker stop *_node2_1`）后它在表里变"离线"、配额被冻结记账，其余
两台分走剩余池；重启后自动纳回。

## 7. 排障

- **节点一直"离线"**：总控容器/机器到节点 `url` 的连通性（节点默认绑
  0.0.0.0，若被改回 127.0.0.1 则只有本机能访问）；
- **节点表"最近错误"列有 401/403**：fleet.yaml 里该节点 token 与节点
  `RL_API_TOKEN` 不一致；
- **"已分配合计"标黄**：有冻结节点在记账占份额（正常，处理掉离线/
  降级节点即恢复），或冻结之和已超总带宽（超卖告警，日志里有明细）；
- **总出向压不到总带宽**：看是哪台节点超——节点表利用率 >100% 的那台
  的内环没收敛，跳到它自己的控制台看"调节视图"（参照
  [09 排障指南](09-排障指南.md) §3）；
- **改了总带宽没反应**：写 API 返回 200 了吗（令牌）？总带宽一变总控
  立即跑一轮分配并下发，节点生效还要再等它自己的内环走几轮；
- **取消总量控制后某节点还限着**：节点表配额列带"待解除"标签 = 它离线
  或解除请求失败（"最近错误"列看原因，401/403 核对令牌），总控每个分配
  周期自动重试、恢复在线即解。
